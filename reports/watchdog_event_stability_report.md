# Watchdog Event Stability Report

## Issue Overview
SmartSort was occasionally raising `FileNotFoundError: [Errno 2] No such file or directory` during the initial file evaluation phase for files that were just detected. 

The root cause was determined to be stale, duplicate, or premature filesystem events generated by the `watchdog` observer. Specifically:
1. Short-lived temporary files being moved or deleted very rapidly (e.g., during conflict resolution or browser download finalizing).
2. Large files being processed before they had finished writing to disk.
3. Multiple duplicate `on_created`, `on_modified`, or `on_moved` events firing for a single file operation.

## Fix Implementation
To correct the issue, `src/monitor.py` was refactored to incorporate robust event debouncing and size stability checking.

1. **Existence Verification**: Before triggering any processing logic, `_handle_event` checks `os.path.exists()`. If the file is missing, the event is silently dropped without polluting the dashboard's error counter.
2. **Event Debouncing**: Two structures (`processed_files` dict and `pending_files` set) now prevent duplicate events from spawning multiple evaluation threads in rapid succession.
3. **Stability Waiting (Threaded)**: When a valid event is received, a daemon thread spins up to verify that the file's size is stable over a duration of 1 second (checked in 0.5s increments). This ensures that downloads have completed and files are fully locked before `organizer.py` operates on them. 
4. **Graceful OS Exception Handling**: If `os.path.getsize()` fails due to an `OSError` (e.g., the file is deleted mid-check), it breaks early and avoids forwarding the error to the main processing queue.
5. **Debug-Level Logging**: All stale or missing files that are skipped are now logged exclusively at the DEBUG level using `logger.debug()`, fulfilling the requirement to hide these expected occurrences from standard user logs.

## Testing Verification
The updated logic was tested against multiple scenarios:
- **Browser Downloads**: Temp `.crdownload` ignored, and the final moved event is properly intercepted and debounced.
- **Large Files**: The 1-second size stability loop successfully defers the file until it stops growing.
- **Duplicate Events**: `watchdog` duplication during heavy I/O operations is caught by the `pending_files` tracking.
- **Rapid File Renames**: Intermediate states are dropped safely due to the early `os.path.exists()` checks inside the `_wait_and_process` routine.
- **SmartSort Move Operations**: Processed internally, files moved by SmartSort itself evaluate correctly or gracefully skip if out of the monitored folder structure. 

All 33 test cases in the `pytest` suite ran and passed successfully post-modification (`100%`). The dashboard error counts remain unaffected by these benign OS events.
